# CCUS Policy Hub：Agent 专业上下文层路线图

状态：功能规格提案，尚不代表各阶段已开工。用户已确认首版服务自己的 Agent，
以美国 45Q 政策问答验收，交付静态 JSON/Markdown，不先建设服务器。

产品目标：**为 CCUS 领域 Agent 提供可引用、可核查、明确证据与时间边界的专业上下文。**
现有人用研究站继续保留；未实现的条款检索、全文语料、MCP 和知识图谱不作为现有能力宣传。

## 当前基线

2026-10-29 核对 `main`（`aa68b45`）的 SQLite：130 条政策、1,110 条设施、65 个国家档案；
设施—政策关联共 4,796 条，其中 4,287 条为 `country`（0.3），509 条为 `subnational_region`（0.75）。
`sector` 和 `evidence` 均为 0；地方匹配被核验也不等于项目法律适用性已获核验。

[#102](https://github.com/liuh886/ccus-policy-hub/pull/102) 已实现关系分类、复核队列、
首批中文分析与数据/界面整改，当前仍待合并。上下文功能应复用其成果，不重复实施。
静态 JSON 已存在，但任务型 bundle、版本化条款与条件卡仍是待建能力。

## 功能与实施顺序

详细需求、契约、模块边界、文档清单和验收用例统一见
[《Agent 上下文层：功能与架构规格》](context-layer-functional-spec.md)。
该文件即本专项 PRD，替代未指定路径的“PRD frontmatter/正文”引用。
当前开发状态统一进入[主路线图](ROADMAP.md)。

| 切片 | 可用功能                                              | 验收与边界                                                                                  |
| ---- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| S0   | 定位与可执行规格                                      | 首用户、45Q 任务、输出形式、数据基线、依赖与退出标准明确                                    |
| S1   | 政策上下文包发现、按 ID 读取、双语 JSON/Markdown 导出 | 六节齐全；IRA/2025 修法分开；来源引用可解析；摘要与条款分级；缺失证据明确；只读且确定性生成 |
| S2   | 官方文本版本、原文定位与人工复核                      | 清单先冻结；原文哈希改变使锚点与抽取审核失效；不自由生成条款                                |
| S3   | 条件卡、缺失信息清单、项目证据关系                    | 条件有时间/例外/出处；未知不算满足；地域匹配不变成抵免证明                                  |
| S4   | MCP/图谱采用评估及可选适配                            | 以真实任务验证为前提；有采用或不采用决策记录即可                                            |

S1 首批包：`us-45q-ira`、`us-obbba-45q-2025` 与政策族 `us-section-45q`。
政策族不是新编的法律整合文本；第一轮只能回答现有记录所支撑的摘要问题。
完整条款级 45Q 条件问答必须先通过 S2/S3，不能以包已生成代替税法事实复核。

## 范围与治理

- Source-sink 匹配不在范围；地理精化仅用于实体身份与位置质量。
- SQLite 继续是结构化事实来源；上下文包是生成物，不能独立手改。
- 不更改现有置信度、评分、Pipeline/Committed 或能力定义。
- 文档/条款存储、schema、关系推导等变更按现有治理规则单独评审。
- 原有数据新鲜度、分析翻译、设施资料与性能维护不取消，进度由主路线图统一管理。
- 每个切片独立 PR、独立验证；合并仍须 CI 与人工审查。
