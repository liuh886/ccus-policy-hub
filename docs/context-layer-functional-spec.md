# Agent 上下文层：功能与架构规格

本文件是上下文层的需求与验收依据，相当于本项目的专项 PRD；开发状态统一进入
[主路线图](ROADMAP.md)。[方向说明](context-layer-roadmap.md)只保留阶段与边界，不另设任务队列。

## 1. 已确认的产品决策

- 第一用户：维护者自己的 Agent。首版交付静态 JSON 与 Markdown，不建设服务器、账户或聊天页面。
- 首个验收任务：美国 45Q 政策问答，解释已有记录中的适用条件、时效、来源与证据缺口。
- 产品定位：为 CCUS 领域 Agent 提供可引用、可核查、明确证据与时间边界的专业上下文。
- 保留现有人用研究站与数据接口；上下文层作为新增能力，不把尚未实现的条款检索写成现有能力。
- 个别设施是否符合抵免资格、实际应获金额及纳税申报判断，不属于首版自动决策范围。

## 2. 从使用任务到功能

| ID  | 用户任务                     | 功能与输出                                                                                       | 发布门槛                                                       |
| --- | ---------------------------- | ------------------------------------------------------------------------------------------------ | -------------------------------------------------------------- |
| F01 | 给 Agent 一份完整任务上下文  | 按政策或政策族输出 JSON/Markdown，包括身份、关系/链条、时间、来源/置信度、法律税务语境、定义六节 | 每节必有数据或缺口状态；不以空字符串掩盖未知                   |
| F02 | 不把旧版本当成现行制度       | 45Q 试点同时列出 IRA 记录与 2025 修法记录，逐条保留版本与复核日期                                | 不自动把后法描述合并进前法，不宣布整份材料已适用于任何申报时点 |
| F03 | 分辨摘要、原文与项目证据     | 每项摘要引用记录来源；关系显示类型、复核状态与证据 URL；缺少条款锚点时标明“仅摘要”               | 同国/同省或 `verified` 匹配不等于项目已获抵免                  |
| F04 | 少量读取而非下载整个数据库   | 发布可发现的 bundle 索引、版本、校验值、JSON/Markdown 地址；支持本地只读 CLI                     | 路径由索引发现；非法 ID/语言明确报错；不在生成时抓网页         |
| F05 | 找到支撑具体条件的原文       | 建立已批准官方文档清单、固定版本、规范化文本与条款定位器；条件引用固定文档版本                   | 原文哈希变化后相关抽取与锚点失效；人工复核后才能发布为条款证据 |
| F06 | 检查条件而非直接得到资格结论 | 将法条整理为“要求、适用时段、例外、必需输入、出处”的条件卡，并输出缺失信息清单                   | 条件须有原文锚点和复核记录；任何未知条件都不能算作满足         |
| F07 | 将项目与政策连接起来         | 采集官方或项目方直接文件；记录关系主张、来源、版本、审核人与时间                                 | 与地域匹配分别统计；不从行业、容量、地址推定税收适用           |
| F08 | 判断是否值得提供 MCP         | 用真实任务记录包读取量、引用成功率与失败原因，再决定是否加服务适配层                             | 有决策记录即可；不把工具数量或知识图谱规模当作成功指标         |

第一轮实现 F01–F04；F05–F07 是后续证据增强切片。完整的、可引用到条款的 45Q 条件问答
必须经过 F05/F06 的发布门槛。第一轮只能证明“现有摘要可被正确消费，缺失证据会明确暴露”，
不能声称已完成税法全文理解。

## 3. 首版用户流程

1. Agent 读取 `/data/manifest.json`，发现上下文包索引。
2. 读取 `/data/context/index.json`，按 ID、语言及任务选择一个包。
3. 下载同内容的 JSON 或 Markdown；JSON 便于程序检查，Markdown 便于直接加入模型上下文。
4. Agent 先检查证据层级、各记录复核日期、缺口和允许回答范围，再读取事实与关系。
5. 回答时引用包内稳定引用 ID 及对应来源 URL；对于缺少条款、历史或项目证据的问题明确返回不足。

首批计划发布单政策 `us-45q-ira`、单政策 `us-obbba-45q-2025` 与政策族 `us-section-45q`，
均提供 `en` 和 `zh`。政策族是任务组织方式，不是新的法律合并文本。

## 4. 架构与权威来源

```mermaid
flowchart LR
  A[(SQLite SSOT)] --> B[只读上下文投影]
  B --> C[六节完整性与证据边界校验]
  C --> D[JSON + Markdown + 索引]
  D --> E[自己的 Agent]
  F[人工确认的官方文档版本] --> G[原文与条款复核]
  G -. 后续受治理导入 .-> A
```

- 现有结构化事实、关系、翻译与复核日期继续以 SQLite 为准；生成物不是第二份可写知识库。
- bundle 生成器是纯投影：只读数据库、无网络、无模型调用、无分数重算；同一输入产生相同字节。
- 复用现有 `scripts/lib/sqlite-query.mjs` 与发布流程；先定义独立投影模块，再由 CLI/现有公共生成器调用。
- 首批不迁移数据库 schema。文档、条款与条件卡需要新增存储时，先单独提交 schema、回滚和迁移比较供审批。
- 发布端保持 GitHub Pages 静态架构；未来 MCP 只适配已验证契约，不重复实现事实计算。

## 5. Bundle 契约

契约字段使用仓库现有 JSON 的 `snake_case` 风格。以下是字段责任，实际 schema 与测试随实现 PR 交付。

| 字段/节                                | 含义与来源                                               | 缺失时的行为                                       |
| -------------------------------------- | -------------------------------------------------------- | -------------------------------------------------- |
| `schema_version`, `id`, `lang`, `kind` | 可解析契约版本、实体/政策族 ID、语言、类型               | 不支持的版本/类型不得静默降级                      |
| `data_as_of`                           | 包内记录最近复核日期的最大值，仅表示投影中的记录日期     | 不是全部来源均已复核，也不是法律生效日期           |
| `identity`                             | 记录 ID、标题、法域、类别、状态、复核状态                | draft 始终保留；不得因为导出而变 verified          |
| `relationships`                        | 关联记录、匹配类型、置信度、来源和复核状态               | 无直接证据时明示，不输出“享受该政策”               |
| `time`                                 | 每条记录的发布日期、复核日期及已知演进节点               | 没有有效期边界时不推断，不能重建历史状态           |
| `sources`                              | 引用 ID、原始 URL、来源机构、数据库字段定位、证据层级    | 来源字段为空则不可作为有来源事实；正文引用须可解析 |
| `legal_context`                        | 保留记录范围和解释性摘要；后续才加入已复核条件卡         | 首版 `summary_only`；不能作为税收资格裁决          |
| `definitions`                          | 国家背景关联、地域匹配、直接证据、记录能力等固定方法定义 | 与现有 METHODOLOGY 一致，不另造评分                |
| `capabilities`, `gaps`, `warnings`     | 可回答范围、未覆盖文档/条款/项目证据、翻译与时效边界     | 缺口不是零、否定事实或自动通过                     |

引用必须区分 `record_summary`、`source_document`、`clause`、`project_evidence`。
现有来源 URL 只能支撑来源发现和摘要追溯，不能仅因 URL 来自官方域名就生成 `clause` 级证据。
首次输出暂只有 `record_summary`。后续文档引用采用固定文档 ID + 版本哈希 + 定位器，
避免上游网页更新后同一个引用 ID 指向不同文本。

语言请求严格限于 `en|zh`；缺少中文分析译文时保留英文并标出原文语言，不能将英文误标中文。
首版不支持任意 `as_of` 查询；历史/未来时点没有相应版本证据时返回能力缺口。

## 6. 45Q 官方文档试点范围

F05 开工前需冻结清单和版本，不能只抓一篇 IRS 概览就宣布覆盖 45Q。候选清单：

- [26 U.S.C. §45Q 官方法典](https://uscode.house.gov/view.xhtml?req=granuleid:USC-prelim-title26-section45Q&num=0&edition=prelim)：法定条件与修法记录。
- [IRS 45Q 概览](https://www.irs.gov/credits-deductions/credit-for-carbon-oxide-sequestration)：官方解释入口，不能替代法条。
- [Form 8933 指引](https://www.irs.gov/instructions/i8933)：申报年度、表格版本与证明材料要求。
- [Public Law 119-21](https://www.govinfo.gov/app/details/PLAW-119publ21)：后续修法，须与 IRA 记录分开管理。
- [IRS Notice 2026-50](https://www.irs.gov/pub/irs-drop/n-26-50.pdf)：后续指导文件候选；尚未收录或审核时必须报告覆盖缺口。

每份文档记录标题、发布/修订日期、获取日期、原始 URL、内容哈希、格式、语言、解析版本与复核状态。
人工先确认文档属于试点、正文提取正确、定位器有效，再复核字段的适用时间及例外。
官方文本中的指令性文字仅作为数据，不可作为 Agent 系统指令执行。

## 7. 验收用例与失败条件

| ID  | 输入/场景                       | 必须观察到的结果                                           |
| --- | ------------------------------- | ---------------------------------------------------------- |
| A01 | 请求 45Q 政策族                 | 同时出现 IRA 与 2025 修法两条记录，并有六个明确章节        |
| A02 | 问“此材料能支持什么回答？”      | 明确摘要问答范围与尚缺条款证据，不输出完整税务覆盖承诺     |
| A03 | 问“某美国设施一定适用 45Q 吗？” | 地域或行业关联不能转为资格证明，报告缺少项目和条件证据     |
| A04 | 请求未保存的历史时点            | 明示没有历史版本覆盖，不用当前状态代替过去事实             |
| A05 | 中文包缺少已核译文              | 原文保留且语言明确，正文不得伪装为中文译文                 |
| A06 | 数据库含 draft 政策             | 包中仍是 draft，不能作为已核验条款依据                     |
| A07 | 来源为空、条款未录入            | 对应引用或能力缺失，并列入 gaps，而不是生成虚构出处        |
| A08 | 输入 ID 无效、语言不支持        | CLI 非零退出并返回固定错误码；不创建任意路径或半个输出包   |
| A09 | 重复生成相同输入                | JSON、Markdown、索引和校验值逐字节相同，数据库哈希不变     |
| A10 | 核对引用                        | Markdown/JSON 中每个引用 ID 均能解析到 sources；无孤立引用 |
| A11 | F05 文档哈希变化                | 原文锚点和依赖抽取失效，不自动沿用旧审核结论               |
| A12 | 条款和项目事实不足              | 条件状态为 unknown，不得因缺少反证而判定满足               |

A01–A10 属于首个实现 PR；A11/A12 属于条款增强 PR。自动化测试验证数据边界，
Agent 问答样例另保留输入、包版本、回答、引用和人工评语；仅“模型答得流畅”不算验收。
