# CCUS Policy Hub — Active Roadmap

> Last reviewed: 2026-11-23. This is the single active task queue. Product scope, architectural responsibilities and stop rules are defined in [PRODUCT_BOUNDARIES.md](PRODUCT_BOUNDARIES.md).

## Goal and baseline

CCUS Policy Hub is a bilingual evidence-grounded research and data platform. It publishes verifiable static Agent-ready data for downstream consumers; it **does not build or evaluate a professional Q&A Agent**.

The mainline baseline includes #102–#105, #108–#111, #113–#114 and #117–#130 (**merged on main**, including PR #129 `fcf5f5fd` and PR #130 `3762d95d`), with 130 policy records (`124` reviewed, `6` draft), 1,110 facility records and 65 country profiles. SQLite (`efc3293c...`) is the authoritative maintenance source; public JSON, Markdown and Astro pages are generated projections.

Passing CI on a feature branch is not proof of public release. Product boundary #105, architecture-research plan #108, consumption specification #109, roadmap reconciliation #110, search-runtime alignment #113, policy/workflow update #102, source-readiness inventory #111, static context contract #103, frozen 45Q source-evidence contract #104, discovery catalog prototype #114, v1.1 UX/link checks #117, SSG data index and externalized payloads #118, 10 policy URL repairs and review audit guard #119, 109 Tier-1 ZH analysis translations #120, P3 cross-jurisdiction reuse #121, governed ingest/subnational matcher hardening #122, declarative registries/layered budgets/archive seam/scaffold #123, unified facility projector/single-lock audit/gen pipeline #124, readiness/runbook/all-packet evidence & lint guards #125, roadmap convergence #126, 150 Tier-2 ZH analysis localizations #127, governed direct relationship evidence importer with 10 verified project–policy evidence links #128, Batch 2 reviewed HTML snapshots (4 packets across 7 total jurisdictions, 20 bilingual context bundles, and 2 verified URL repairs) #129 (`fcf5f5fd`), and Architecture Slice E (unified evidence packet loader, `external_archive` readiness validation, `evidence:consume` decoupling from `context-targets`, clean-sync stale-file pruning, `policy_review_attempt` provenance preservation, and zero-churn scaling tests) #130 (`3762d95d`) have **merged on main**; superseded/unmerged experiments #101, #107, #112, #115 and #116 are **closed without merge**.

## P2 — Review and publish citable original-source evidence (Baseline Prototype Completed on `main`)

- **Input:** P1, #106 audited source gaps, #104/#121's merged Git HTML evidence packets, #123's `external_archive` storage seam and `evidence:scaffold`, #130's unified evidence packet loader and `external_archive` readiness validation, and [#108 source-to-citable-context research](https://github.com/liuh886/ccus-policy-hub/pull/108).
- **Discovery catalog prototype (#114/#121/#123/#129):** Projects the `8` frozen Git HTML packets (`us-45q-usc-2024`, `ca-ccus-itc-2026`, `no-for-2014-1517`, `dk-ens-ccs-funds`, `cn-ccer-2026`, `us-epa-class-vi-primacy`, `uk-ccus-vision`, `eu-innovation-fund-ec`) and `2` explicitly captured archived PDFs (`uk-energy-act-2023-enacted`, `gccsi-ccus-progress-china-en`) into `public/data/discovery/catalog.json` (`10` records / `10` receipts / `8` reviewed catalog references). The independent `catalog:consume` consumer resolves selected versions/locators (`8` HTML packets as `reviewed_historical_locator`, and both PDFs as `candidate_only` with explicit private-byte, edition and review gaps) without rerunning discovery/acquisition or performing semantic knowledge extraction.
- **Work — source repair (ongoing under #106):** Validate identity/issuer/instrument/edition for archived candidates using actual original bytes; repair broad homepage or broken/redirected URLs to precise official documents through reviewed SQLite changes (such as #119's 10 verified URL repairs and #129's 2 verified URL repairs). **No guessing or silent URL rewriting.**
- **Work — publication:** Only after issuer, edition, quote/page or clause, and human-review scope are confirmed, publish minimal citable evidence. Report summaries remain **secondary sources**; neither PDFs nor web pages automatically substantiate legal applicability. Preserve historical editions and reject stale/altered/unreviewed citations.
- **Done:** #104, #114, #121, #123, #125, #129 and #130 demonstrate concrete HTML snapshots across 7 jurisdictions (US, CA, NO, DK, CN, UK, EU) and UK-law/GCCSI PDF specimens with evidence identities, format-specific locators, licensing and review scope; independent consumers (`evidence:consume` decoupled from `context-targets` in #130, `catalog:consume`) and all-packet inspection (`evidence:inspect`) resolve approved references to immutable version/hash/locator and surface draft/restricted/currentness gaps. For #106 each policy's source readiness remains visible; previously verified evidence regressions fail validation, not-yet-reviewed legacy records remain known backlog.
- **Stop:** Eight historical HTML packets and two candidate PDFs prove the mechanism, not readiness of 130 policies. Do **not** copy licensed/private Drive PDFs into public Git or publish large text without permission. No automatic eligibility, bulk condition cards, generic crawler or unapproved SQLite migration. Prefer versioned Git evidence files (when redistributable) + existing SQLite records; no duplicate BLOB full text.

## Required evidence for each implementation PR

- State the accepted authority input and generated output.
- Document schema/field meanings, missing-value states, source versions, review and language status.
- Verify citation integrity, negative cases and deterministic generation.
- Confirm SQLite consistency and the correct release state: implemented on branch, merged on main, or published on Pages.
- Explain why any new service, table, dependency or subsystem is necessary for a tested consumer or maintenance need.
