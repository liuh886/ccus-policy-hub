# CCUS Policy Hub：Agent 专业上下文层路线图（PR 草稿）

> 状态：提案，Draft PR，不合并即不代表全部开工；每个阶段单独成 PR 逐步落地。
> 仓库现状（2026-10-28 核查）：main `aa68b45`，130 条政策、1,110 条设施记录、65 个国家治理画像；
> 设施数据集版本 2026-Q2，README last checked 2026-06-24；`docs/ROADMAP.md` 最后更新 2026-09-23；
> 目前无 open issue / open PR；最近人工提交为 2026-10-22。

## 定位（一句话）

CCUS Policy Hub 从“全球情报基础设施 / 人用的研究站”，收敛为
**CCUS 领域 Agent 的专业上下文层**：给 Agent 一份可引用、可核查、有置信度边界的上下文，
而不是一堆网页和静态 JSON。

## 边界（本路线图明确不做 / 不宣称）

- Source-sink 匹配不在范围；地理精化只用于节点身份与位置质量，不用于匹配距离。
- 知识图谱只是现有关系 / JSON Schema 模型的导出映射候选，不是重建本体，不是已建成。
- 不宣称已建成条款级语义检索、GraphRAG、MCP 服务或全文文本层——这些是本路线图的待建项。
- 不因为本路线图就取消现有 backlog：数据新鲜度、内容深度尾部、i18n 收敛、
  `facilities.json` 瘦身仍是独立轨道，另行排期。

## 阶段 0：先对齐定位，再开工

- 对齐 PRD frontmatter north_star、PRD 正文顶部、README、`llms.txt` 的定位表述，
  消除“全球领先、DOI 认证的开源研究中台”与“专业上下文层”并存的冲突。
- 验收：同一句话在上述四处一致；不改数据、不改 schema、不改前端功能。

## 阶段 1：静态上下文包（不先做 server）

- 用现有 SQLite SSOT + JSON 生成能力，为一个实体输出一份可引用的 context bundle。
- 六层齐全：身份、层级 / 链条、时间、来源 / 置信度、法税约束、定义。
- 验收：一个真实 Agent 任务只凭这份 bundle 就能回答问题并给出引用，
  且低置信度链接在 bundle 里显式标注、不被包装成高置信度结论。
-  bundle 示例实体、任务用例在本阶段开始前由维护者确认。

## 阶段 2：文本层试点——美国 45Q

- 现状缺口：政策记录目前只有元数据、双语标题 / 描述 / 范围 / 标签、
  FSRTM 五维评分与分析解读，没有全文语料、条款字段与条款抽取。
- 试点：对 45Q 相关法条 / 官方文件做文档理解解析、schema 约束抽取、条款锚点，
  全部经过人工复核后才入库；不做无约束的自由抽取。
- 验收：试点文档集的条款锚点可回溯到原文位置，抽取字段符合既定 schema，
  人工复核记录可查；试点文档范围在开工前确认，不默认覆盖全部美国政策。

## 阶段 3：证据级链接（与文本层一起做，不单扩国家级链接）

- 现状：6,992 条设施–政策链接全部是国家级、低置信度 0.3；
  sector 级 0 条，evidence 级 0 条。这是上下文层可信度最弱的一环。
- 顺序：先定 sector 级推导规则，再做少量 evidence 级链接（例如设施获得 45Q 抵免的
  直接证据），并补齐 review workflow；质量指标随之更新。
- 验收：sector / evidence 链接数、来源与复核状态在质量输出中可见，
  不再把 0.3 的国家级链接默认当作项目级法律适用性。

## 阶段 4：MCP 与知识图谱——只在 bundle 被验证后评估

- MCP：仅在阶段 1 的 bundle 被真实任务验证后才做，候选 5–9 个工具，
  工具清单以验证结果定，不先定死。
- 知识图谱：只作为现有关系模型的导出评估，是否做、做到什么程度由评估决定。
- 验收：有明确的采用 / 不采用决策记录；不采用也是一种完成。

## 落地方式

1. 本 PR 只定路线与验收标准，不含代码与数据改动。
2. 阶段 0–4 各自单独开 PR，单独 review、单独合并。
3. 每阶段开始前确认该阶段的试点范围与第一用户。
